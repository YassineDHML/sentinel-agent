1. What Sentinel is

Sentinel is a weekly automated pipeline that watches the AI-tooling market. Each week it collects industry news from several sources, filters and deduplicates it, uses an LLM to summarize and tag each article, tracks how topics evolve over time, generates an HTML report, and emails it to the team — running autonomously in the cloud, on free tiers only.

① Workflow, not an agent

The steps run in a fixed order (A→B→C→D). The LLM is used only inside two narrow, controlled steps — it never decides the control flow. This makes the system predictable, debuggable, and reliable for an unattended weekly job.

② The database is the memory

Cloud runners are ephemeral (wiped after each run), so all state — article history, weekly topic counts, past reports — lives in Supabase. "Is this trend accelerating?" means reading the last 4 weeks back out of the database and comparing.

3. The pipeline, stage by stage

StageWhat it doesKey detail worth knowing
1 · Collect Pulls raw articles from 5 sources into one uniform shape. RSS, Hacker News, Product Hunt, Google News, GNews. Each behind its own module; a dead source is skipped, never fatal. RSS/APIs preferred over scraping (cloud IPs get blocked).
2 · Process Drops off-topic articles, removes duplicates, saves new ones. Relevance = keyword/actor match (word-boundary aware, so "AI" ≠ "email"). Dedup = exact URL + title-similarity grouping. Only genuinely-new URLs are stored (processed=false).
3 · Fulltext Fetches the full article body for the batch about to be analyzed. Collectors only give title + snippet; the LLM needs the body. robots.txt-aware, polite delay, 429 backoff + per-host circuit breaker. Fetched text is cached in the DB (fetched at most once).
4 · Analyze LLM writes a 3–5 line summary and assigns canonical topic tags. Batched (8 articles/call) to respect rate limits. Gemini primary, Groq fallback for light tasks. Tags must come from a fixed list — invented tags are rejected.
5 · Trends Counts topics for the week, labels each NEW / ONGOING / ACCELERATING. Pure arithmetic, no LLM. Compares this week's counts against the prior 4 weeks read from the DB. Produces a compact "trend digest".
6 · Report Builds the narrative + renders the HTML report, archives it. One Gemini-only "deep analysis" call → exec summary, competitive watch, opportunities. Trends & sources sections are deterministic. Every claim must cite a real source URL.
7 · Deliver Emails the report; posts a Slack notification. Gmail SMTP (app password). Slack optional. Email failure is loud (fails the run) but the report is already archived.

6. Design decisions

Tiered LLM fallback (not a mirror)

Groq's free budget (12k tokens/min) is too small for historical analysis, so it only ever handles light tasks; the heavy analysis stays Gemini-only. Never cram history into the small model.

Canonical topic list

The LLM tags into a closed list of ~20 topics; invented labels are dropped. This is what makes week-over-week trend counting reliable.

Citations enforced in code

Every report claim must cite a source article number; the parser resolves it to a real URL and deletes any uncited statement. Anti-hallucination is guaranteed, not just requested.

Graceful degradation everywhere

A dead source, a rate-limited host, a bad LLM response, even a missing LLM — each degrades and logs rather than crashing the weekly run. Email failure is the only "loud" failure.

Free-tier by design

Batching, an analyze cap, discovery-only sources, and a DB keep-alive all exist to stay within free quotas. Total running cost: 0 €.

Reproducible & tested

Strict version pins; 148 automated tests that run without any secrets (mocked externals) — the safety net for evolving the code.

Known limitations

  • Google News gives redirect URLs — full text can't be fetched for those items yet (they fall back to snippet/title).
  • Title-similarity dedup is best-effort — headlines differing only by a name/number can over-merge. Exact dedup (by URL) is guaranteed; the threshold is tunable.
  • Analyze cap (25/run) is a free-tier trade-off — not every collected article is summarized. Raising it is a config change, within quota.
